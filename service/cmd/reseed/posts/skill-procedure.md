系统提示里写“遇到数据库问题就仔细处理”，模型每次都会重新决定步骤。Skill 把已经做过的一种任务固定下来：出现哪些说法时阅读这份规程，按什么顺序做，哪一步之后必须停，最后交回什么。

触发写窄一点。标题和描述里出现“慢查询”“执行计划”“索引”时再使用，而不是任何带 SQL 的句子都使用。触发太宽，不相关的任务也会把整份规程读进上下文，后面的指令被这份规程带跑。触发太窄，该用的时候模型看不到。可以在描述里各给两三个正例和反例，反例和正例同样重要。

正文用步骤，不用形容词。例如：先拿到完整 SQL 和表结构；再看过滤条件、排序和 LIMIT 是否能对应到索引列顺序；给出一个可能的索引之前，先说明它帮到哪条访问路径，以及会让哪类写入多维护一棵索引。不要写“给出最优索引”。最优依赖数据分布，规程里没有统计信息时不应假装有。

停的条件写在步骤中间，不要只写在最后。缺少 SQL 原文、看不到 `EXPLAIN`、表结构来自猜测，这三件事任何一件成立，就列出缺什么并停止，不要继续给索引建议。模型最容易在信息不足时把建议写完整，因为完整看起来像做完了。

输出固定成几节即可：现有访问路径、建议改动、改动影响的写入、还缺的信息。调用方看到空的“还缺的信息”并且前三节有内容，才算这份技能跑完。结构不固定时，无法判断它是做完了还是停在半路。
