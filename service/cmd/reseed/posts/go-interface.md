title: 赋给接口的值，编译器经常把它放到堆上
publishedAt: 2026-04-22
category: Golang
tags: Interface, Escape Analysis
---

接口值在运行时是两个指针：一个指向类型信息，一个指向数据。函数返回这个接口值，或者把它放进别的 goroutine 也能读到的结构里时，数据指针在当前栈帧销毁后仍要有效。编译器若不能证明数据只活在当前栈上，就会在堆上分配，再让接口指向堆内存。

下面这个函数把一个局部的结构装进接口并返回。调用结束后栈帧没了，接收方还要读字段，于是 `p` 逃逸：

```go
type Point struct{ X, Y int }

func newPoint() any {
    p := Point{X: 1, Y: 2}
    return p
}
```

若签名直接返回 `Point`，并且调用方不再把它的地址传出去，编译器可以把 `p` 留在栈上。返回具体类型还是返回接口，差别经常体现在分配剖面里，而不是体现在那一次类型断言的耗时上。断言本身是比较接口里的类型指针。热路径上先装箱成 `any` 再断言回 `Point`，多付的是分配和后续扫描。

`go build -gcflags=-m` 会打印“escapes to heap”以及原因，例如 “leaking param” 或 “moved to heap: p”。原因不固定，改一行调用方式就可能变。没有这段输出就改接口，容易把分配留在原处，只是代码更难扩展。

剖面里分配占比不高时，接口留着更清楚。占比高、且逃逸原因指向某几个装箱点，再把那几个签名改成具体类型。优化的对象是剖面里的热点，不是所有用了接口的地方。
