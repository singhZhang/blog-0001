title: FPM 的 worker 比单次请求活得久
publishedAt: 2025-03-06
category: PHP
tags: PHP-FPM, Process
---

php-fpm 的一个 worker 一次只处理一个请求。请求结束时，这次请求的局部变量会销毁，连接上输出已经发完。worker 进程通常不退出，接着接受下一个请求。pm = static 时进程数固定；pm = dynamic 时在 min 和 max 之间伸缩。无论哪一种，进程复用都是常态，不是例外。

因此静态变量、类的静态属性、扩展在进程里初始化的缓存，都会跨请求保留。第一个请求把租户 ID 放进静态变量，第二个请求如果没覆盖它，读到的仍是第一个租户。这和“PHP 每次请求都是干净的”不矛盾：干净的是符号表里的局部变量，不是进程地址空间里你主动留下来的东西。

单例也一样。单例存在于进程里，不存在于某一次请求里。若单例在第一次使用时读取配置并缓存，配置在不重启进程的情况下变更，这个 worker 会一直用旧值，直到它被回收。opcache 能更新字节码，但更新不了已经放在静态变量里的旧数组。

进程数会放大外部连接。每个 worker 若各自持有一条数据库连接，max_children = 50 就可能是 50 条连接，再乘以机器数。数据库先打满，PHP 的 CPU 还空着。慢日志里若同时出现大量请求堵在 accept 队列，则是 worker 太少或单个请求太慢，和索引无关。

要确认状态有没有串，可以在请求结束时把静态缓存清掉，或者把缓存键里放上请求级的租户。更直接的办法是看 worker 的请求计数：pm.status_path 打开后，能看到每个进程处理了多少请求。一个进程处理了上千次仍不回收时，就要假定它身上任何静态值都活了那么久。
