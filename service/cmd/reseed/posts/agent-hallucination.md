智能体语境里的幻觉，指模型写出了当前观察里不存在的内容，并把这段内容继续当成后续步骤的依据。它不限于“编造一篇论文”。在会调用工具的循环里，更常见的是补上一次并不存在的查询结果、一个没有返回的字段，或一次实际没发出去的工具调用。

## 观察和续写不是同一来源

模型每次生成，都是在已有 token 后面继续采样。工具返回的 JSON、报错、空列表，只有被放进上下文，才会成为这些 token 的一部分。上下文里没有的订单号、价格、用户原话，模型仍然可能按语言习惯补出来。补出来的句子读起来完整，是因为训练数据里完整的句子更多，不是因为工具真的返回了这些字段。

因此要先分开两件事。一是工具进程的标准输出或 HTTP 响应，二是模型在这之后写的话。前者可以对照日志核对，后者只是文本。把两者都叫“结果”，排查时就会分不清是接口错了，还是模型在接口之外又写了一段。

## 三种常见的补写

### 给缺失字段填一个看起来合理的值

查询返回 `{ "id": "B8831", "status": "shipped" }`，没有金额。模型若接着写“订单金额为 128 元”，这 128 不是观察的一部分。它来自同类句子里金额经常出现在状态后面。schema 没要求这个字段，校验也不会拦住这句话，因为它出现在工具调用之外的自由文本里。

### 把上一次的观察套到这一次

上一单查到了地址，这一单的查询还没返回，回答里已经写上了同一个地址。上下文窗口里两段 JSON 靠得很近，模型没有用请求 id 把它们分开。若提示里只说“根据查询结果回答”，却不要求引用本次调用的 id，这种串单会反复出现。

### 描述一次没有执行的调用

模型写出“已经发送退款请求”，但运行日志里没有对应的函数调用。这经常发生在模型被允许用自然语言报告进度的时候。进度句和真正的调用记录不是一回事。循环若只把最终自然语言展示给用户，用户无法区分“打算调用”和“调用已返回”。

## 能核对的内容只来自工具返回

约定回答里的每个事实都能指回某一次调用的某个字段。做不到时就写不知道，并给出缺的是哪一次调用、哪一个字段。例如：“get_order 返回的对象里没有 amount，不能给出金额。”这句话可以核对。 “金额大概是 128 元”不能核对。

引用时带上调用序号或幂等键，避免两段相似 JSON 混在一起。退款、改价、发通知这类命令，只有在当次调用返回成功之后才能说已经完成。返回是 timeout 或连接断开时，状态是未知，不是失败，也不是成功。未知不能靠再生成一句更确定的话变成已知。

## 自由文本里的幻觉，校验器看不见

JSON schema 能拒绝非法参数，拒绝不了参数合法之后的自由发挥。模型用合法的 id 调用了查询，又在总结段写了 schema 以外的情节，校验器不会报错。所以总结段也要受约束：要么只允许引用工具结果里的路径，例如 `result.status`，要么先把总结限制成固定槽位，槽位以外的句子不展示给用户。

槽位可以很笨，但笨是优点。例如只填充 `order_id`、`status`、`carrier` 三个键，值必须是某次结果的子串。填不上就留空。空着比写一个流畅的错误句子更有用，因为空着能被程序看出来。

## 日志里至少留下这四样

每次循环保存：模型发出的函数名和参数、校验是通过还是拒绝、工具的原始响应、最终展示给用户的文本。四样对齐之后，幻觉会落在一个具体位置。参数被拒绝却仍然出现在最终文本里，说明拒绝没有回到上下文。响应里没有的字段出现在最终文本里，说明总结步骤没有按字段拷贝。响应里有、最终文本写错，说明拷贝或格式化出错，这和模型采样无关。

没有这四样，只能看着一段通顺的话猜测。通顺不能当作已经调用过的证据。目录里的这几节，就是为了把“话写出来了”和“工具返回了”拆开核对。
